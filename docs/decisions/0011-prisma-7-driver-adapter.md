# 11. Prisma 7 with the `pg` driver adapter

- Status: accepted
- Date: 2026-09-20

## Context

Prisma 7 removed `url` from the schema's datasource block. A connection now
comes from a driver adapter passed to the client, and the migration CLI reads
its own `prisma.config.ts`.

## Decision

Adopt it rather than pinning back to Prisma 6:

- `PrismaService` builds a `PrismaPg` adapter from the **validated app config**,
  so the database URL goes through the same zod schema as everything else and
  there is no second path to `process.env`.
- `prisma.config.ts` supplies the URL for `migrate` and `generate` only.
- The client is generated into `src/generated/prisma` as CommonJS, gitignored,
  and regenerated by `build`, `dev` and `typecheck`.

Query logging is off. Prisma's `query` log level would write note content to
stdout on every write, which the project forbids.

## Consequences

- One more dependency (`@prisma/adapter-pg`, `pg`), and connection pooling is
  now `pg`'s to configure rather than Prisma's.
- The generated client is a build artefact, so a clean checkout must run
  `prisma generate` before `tsc` — which every script that needs it already does.
